# agentrix-agent

Agent definitions for the [Agentrix](https://agentrix.xmz.ai) platform. Each agent is a declarative directory specification — the platform's ClaudeWorker reads the directory, assembles a Claude instance with the agent's configuration, system prompt, plugins, and tools, then makes it available to users.

This repo contains two agents: **Embla**, a meta-agent that builds other agents, and **Web Designer**, an example agent created by Embla.

---

## Agents

### Embla — Agent Builder

Embla is a conversational meta-agent that guides users through designing and scaffolding custom agents. It is itself built with the same plugin-based architecture it creates, making it a working demonstration of the patterns it teaches.

**Capabilities:**
- Interviews users to discover real requirements
- Decides the right component type (skill, MCP tool, hook, command) for each capability
- Generates the complete agent file structure using MCP tools
- Optionally creates an AI-generated avatar
- Registers the finished agent in the Agentrix database

### Web Designer (Example Agent)

A specialized frontend/web design agent generated by Embla. Supports HTML/CSS, Tailwind CSS, React, color palette generation, responsive design, SEO optimization, and browser automation. Included as a reference for what Embla produces.

## Architecture

### How Agents Are Loaded

The Agentrix platform's **ClaudeWorker** loads an agent by reading its directory:

1. `agent.json` — identity (name, version, description)
2. `.claude/config.json` — permission mode, allowed tools, MCP plugin references
3. `.claude/system_prompt.md` — full behavior definition (replace or append mode)
4. `.claude/plugins/` — auto-discovered; each subdirectory is a plugin

### Agent Directory Layout

```
embla/
├── agent.json
├── README.md
└── .claude/
    ├── config.json
    ├── system_prompt.md
    └── plugins/
        ├── embla-tools/          # TypeScript MCP plugin (core tools)
        │   ├── .claude-plugin/
        │   │   └── plugin.json
        │   ├── src/
        │   │   ├── index.ts
        │   │   └── tools/
        │   └── skills/           # Creator skills (SKILL.md files)
        ├── context7/             # External MCP: library documentation
        └── image-generator/      # External MCP: AI image generation
```

### Component Types

| Component | Purpose | Cost |
|-----------|---------|------|
| **Skills** | On-demand knowledge loaded by Claude (SKILL.md files) | Only when relevant |
| **MCP Tools** | Deterministic actions, external APIs, env var access | Always in context |
| **Hooks** | Event-driven automation (PreToolUse, SessionEnd, etc.) | Zero context cost |
| **Commands** | User-invokable slash command shortcuts | On invocation |

### Component Decision Tree

When designing a new capability, apply this decision tree in order:

1. **Already built-in?** (Read, Write, Git, Bash) → Don't create anything
2. **Fixed flow + fixed trigger timing?** → Hook (preferred — zero context cost)
3. **Needs env vars or external API?** → MCP Tool
4. **Optional with more than 3 related operations?** → Skill (avoids context pollution)
5. **Needs AI creativity?** → Skill
6. **Default** → MCP Tool

## Getting Started

### Build embla-tools

```bash
cd embla/.claude/plugins/embla-tools
yarn install    # Install dependencies
yarn build      # Compile TypeScript to dist/
yarn dev        # Watch mode
yarn clean      # Remove dist/
```

The compiled output at `dist/index.mjs` is loaded by ClaudeWorker via the `sdkMcpTools` config field.

| Package | Purpose |

| `zod` | Input schema validation for MCP tools |

## Embla Workflow

When a user asks Embla to build an agent, it follows this five-step process:

1. **Discovery** — Ask questions to uncover real requirements and decide components
2. **Design** — Draft a full plan applying the component decision tree
3. **Confirm** — Present the plan and get explicit user approval before generating
4. **Generate** — Execute tools in sequence:
   - `write_agent_structure` → `create_plugin` → write content files → `validate_agent` → (optional) generate avatar → `save_agent_in_db`
5. **Complete** — Show the agent location, list required env vars, offer next steps

---

## Embla MCP Tools

| Tool | Description |
|------|-------------|
| `write_agent_structure` | Creates the agent directory with `agent.json`, `config.json`, and optionally `system_prompt.md`. **Call first.** |
| `create_plugin` | Creates a plugin directory with `.claude-plugin/plugin.json` manifest and README. |
| `validate_agent` | Validates the agent structure — checks `agent.json`, `config.json`, plugin manifests, skill placement, and path conventions. |
| `save_agent_in_db` | Registers or updates the agent in the Agentrix database. Handles avatar upload, env var schema, and UI customization. Uses `id.txt` for idempotent create/update. |

## AgentrixContext

MCP tools and hooks receive an injected `AgentrixContext` at runtime (never read env vars directly in system prompts):

```typescript
// All MCP tools and hooks export a factory function
export default (context: AgentrixContext) => createSdkMcpServer({
  tools: [
    tool({
      name: "my_tool",
      handler: async (input) => {
        const workspace = context.getWorkspace();
        const userId = context.getUserId();
        // ...
      }
    })
  ]
});
```

Key APIs: `getWorkspace()`, `getTaskId()`, `getUserId()`, `getChatId()`, `createAgentBuilder()`, `startSubTask()`, `sendMessage()`, `showModal()`
